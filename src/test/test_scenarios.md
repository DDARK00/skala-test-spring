# test_scenarios.sh 설명

SKALA-SHOP API의 핵심 비즈니스 시나리오를 curl + jq로 자동 검증하는 통합 테스트 스크립트.

## 실행 전제

- 서버가 `localhost:8080`에서 **data.sql이 반영된 초기 상태**로 기동 중이어야 함
- `ddl-auto: create-drop`이므로 재기동할 때마다 데이터가 초기화됨 → **스크립트를 다시 돌리기 전엔 항상 서버를 재기동**할 것
- `jq` 필요 (`brew install jq` / `apt install jq`)

## 실행 방법

```bash
chmod +x test_scenarios.sh   # 최초 1회
./test_scenarios.sh
# 또는 권한 문제 시
bash test_scenarios.sh
```

## 구조

| 구성 요소 | 역할 |
|---|---|
| `request()` | curl 호출을 감싸는 공통 함수. method/path/cookie/body를 받아 `상태코드\n응답바디`를 반환 |
| `assert_status()` | 실제 HTTP 상태코드와 기대값을 비교해 PASS/FAIL 출력 |
| `assert_eq()` | 응답 바디에서 jq로 뽑은 값과 기대값을 비교해 PASS/FAIL 출력 |
| `[1]~[12]` 블록 | 시나리오 단위 테스트. 순서대로 실행되며 이전 블록의 결과(포인트 잔액, 보유 수량)에 의존 |

## 검증 시나리오 목록

| 번호 | 시나리오 | 검증 포인트 |
|---|---|---|
| 1 | 신규 회원가입 (point 미지정) | 서버 기본 포인트 정책값 적용 |
| 2 | 로그인 | 200 OK + Cookie(`bff-access`) 발급 |
| 3 | 상품 목록 조회 | 인증 없이 접근 가능 |
| 4 | 인증 없이 주문 시도 | 401 Unauthorized |
| 5 | 재주문 (기존 보유 상품) | 수량 누적 + 포인트 정확히 차감 |
| 6 | 내 정보 상세 조회 | 누적된 수량이 응답에 정확히 반영 |
| 7 | 신규 상품 최초 주문 | 새 보유 항목 생성 + 포인트 차감 |
| 8 | 일부 수량 취소 | 포인트 환급 + 수량 차감(row 유지) |
| 9 | 전량 취소 | 포인트 환급 + row 삭제(목록에서 사라짐) |
| 10 | 포인트 부족 주문 | 409 Conflict, `INSUFFICIENT_FUNDS` |
| 11 | 없는 상품 조회 | 404 Not Found, `DATA_NOT_FOUND` |
| 12 | 필수값 누락 요청 | 400 Bad Request, `PARAMETER_EXCEPTION` |

## 시나리오 확장/수정 방법

- **새 테스트 추가**: `[N]` 블록 하나를 복사해서 `request()` 호출과 `assert_*` 몇 줄만 채우면 됨. JUnit처럼 클래스 구조를 새로 짤 필요 없음
- **응답 필드명이 바뀐 경우**: 해당 `jq -r '.필드명'` 부분만 수정
- **인증 방식이 바뀐 경우**(Cookie → Header 등): `request()` 함수 하나만 수정하면 전체 테스트에 일괄 반영
- **에러코드가 추가/변경된 경우**: 해당 `assert_eq "errorCode = ..."` 줄만 수정

## 알려진 제약

- **순서 의존적**: 5·7번이 만든 상태를 8·9번이 그대로 사용하므로, 특정 블록만 따로 재실행하면 정확한 검증이 안 됨. 전체를 순서대로 실행해야 함
- **매 실행 전 서버 재기동 필요**: data.sql 초기 상태를 다시 깔아야 스크립트의 기대값(포인트 잔액 등)이 맞음
- **동시성 미검증**: 이 스크립트는 순차 실행만 다루며, 비관적 락 등 동시 요청 시나리오는 별도 테스트로 다뤄야 함 (고급 기능 단계 예정)
